# 🚀 Site Monitor

**Site Monitor** — это современный, масштабируемый и высокопроизводительный сервис для мониторинга доступности веб-сайтов. Построенный на базе новейшего асинхронного стека Python, проект легко справляется с параллельной проверкой множества ресурсов, предоставляя как удобное REST API, так и мощный инструмент командной строки (CLI).

---

## ✨ Ключевые возможности

*   ⚡ **Абсолютная асинхронность:** Сердце проекта — `FastAPI`, `asyncio` и `aiohttp`. Никаких блокирующих вызовов — максимальная производительность при проверке сотен сайтов одновременно.
*   🔐 **Защищенное REST API:** Полноценное API с интерактивной документацией (Swagger UI) и надежной JWT-авторизацией. Управляйте пользователями и мониторами безопасно.
*   ⏱️ **Встроенный фоновый воркер:** Добавьте сайты в мониторинг, и встроенный фоновый процесс будет автоматически проверять их статус с заданным интервалом, аккуратно сохраняя историю в базу данных.
*   💻 **Мощный CLI-интерфейс:** Не хотите поднимать сервер? Используйте `monitor.py` для мгновенных проверок списков сайтов прямо из терминала.
*   🐳 **Готовность к Production (Docker):** Полностью контейнеризированная среда. Запуск базы данных, применение миграций и старт приложения осуществляются одной командой `docker compose up`.
*   📦 **Современная работа с БД:** Использование `SQLAlchemy 2.0` в асинхронном режиме вместе с `PostgreSQL` и управлением миграциями через `Alembic`.
*   🧪 **Надежность:** Проект покрыт автотестами (API, CLI, фоновые задачи) с использованием `pytest` и тестовой in-memory БД SQLite.

---

## 🛠 Стек технологий

*   **Backend:** Python 3.10+, FastAPI
*   **Сетевые запросы:** aiohttp
*   **База данных:** PostgreSQL, asyncpg (драйвер)
*   **ORM & Миграции:** SQLAlchemy 2.0 (Async), Alembic
*   **Безопасность:** passlib, bcrypt (хэширование), JWT
*   **Тестирование:** pytest, pytest-asyncio
*   **Инфраструктура:** Docker, Docker Compose

## 🚀 Быстрый старт (Docker)

Самый простой способ запустить проект со всей инфраструктурой — использовать Docker.

1.  **Склонируйте репозиторий:**
    ```bash
    git clone https://github.com/amboy1/site-monitor.git
    cd site-monitor
    ```

2.  **Запустите контейнеры:**
    ```bash
    docker compose up --build
    ```
    *Что произойдет? Автоматически скачается образ PostgreSQL, поднимется база данных, Alembic накатит все необходимые миграции, и запустится FastAPI-сервер.*

3.  **Откройте API:**
    Перейдите в браузере по адресу [http://localhost:8000/docs](http://localhost:8000/docs). Вы увидите интерактивную Swagger-документацию, где можно протестировать все эндпоинты.

## 💻 Использование CLI (Командная строка)

В проекте есть удобная утилита `monitor.py`, позволяющая запускать проверки без поднятия веб-сервера.

Сначала установите зависимости локально:
```bash
pip install -r requirements.txt
```

**Единоразовая проверка (Check):**
Проверяет список сайтов параллельно и сразу выводит результат.
```bash
# Проверка конкретных URL
python monitor.py check https://google.com https://github.com

# Проверка сайтов из файла (каждый URL с новой строки)
python monitor.py check --file sites.txt --timeout 10
```

**Режим постоянного мониторинга (Monitor):**
Запускает бесконечный цикл проверок с заданным интервалом.
```bash
python monitor.py monitor https://google.com --interval 60
```

## 🌐 Использование API

Если вы запустили проект через Docker (или локально через Uvicorn), вам доступно мощное API (по умолчанию на `http://localhost:8000/api/v1/...` и других путях, описанных в Swagger).

### 1. Единичные и массовые проверки (Без БД)
Идеально для разовых задач:
*   `POST /api/v1/check` — Проверить один URL (передайте JSON с `url` и `timeout`).
*   `POST /api/v1/check/batch` — Параллельная проверка списка URL (передайте массив `urls`).

### 2. Управление мониторами (Требует авторизации)
Зарегистрируйтесь и авторизуйтесь, чтобы добавить сайты в постоянный мониторинг.
*   **Регистрация:** `POST /api/users/register`
*   **Авторизация (Получение JWT):** `POST /api/users/login` (или `POST /api/auth/token`)
*   **Добавление сайта:** `POST /api/monitors` (Сайт будет подхвачен фоновым воркером)
*   **Просмотр истории:** `GET /api/monitors/{id}/history` (Узнайте время ответа и статус-коды за прошедшее время)

## 🧪 Запуск тестов

Проект имеет отличную тестовую базу. Тесты используют легковесную SQLite базу данных в памяти, поэтому для их запуска не нужен PostgreSQL.

```bash
# Установка тестовых зависимостей
pip install -r requirements.txt

# Запуск всех тестов
pytest
```
Тесты проверяют логику работы API, аутентификацию, воркер и CLI-интерфейс.
